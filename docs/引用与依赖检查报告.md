# 引用与依赖检查报告

本文档汇总项目中的**引用问题**与**库版本/依赖问题**，以及已做修复与建议。

---

## 一、已发现并修复的问题

### 1. go.mod 版本格式错误（已修复）

**现象：**

- `go version '1.24.0': must match format 1.23` —— Go 版本须为合法格式（如 1.20、1.21）。
- `unknown directive: toolchain` —— 当前环境为 **Go 1.20**，不支持 `toolchain` 指令（Go 1.21+ 才支持）。

**修复：**

- 已将 `go.mod` 中：
  - `go 1.24.0` 改为 **`go 1.20`**（与当前环境一致）。
  - 删除 **`toolchain go1.24.7`** 行。

**你本地：**

- 若使用 Go 1.21 及以上，可自行改回如 `go 1.21`，并可选加回 `toolchain go1.21.x`。

---

## 二、依赖与构建说明（无引用错误时）

### 1. 默认构建（不包含 OPC-UA）

- 命令：`go build ./...` 或 `go build -o server.exe ./cmd/server`
- **不会**编译 `serial/opcua.go`（该文件带 `//go:build gopcua`），会使用 `serial/opcua_stub.go` 桩实现，无需 `github.com/gopcua/opcua`。
- 若出现 “找不到包” 等错误，多半是**网络/代理**导致 `go mod download` 未完成，而不是代码引用错误。

### 2. 带 OPC-UA 的构建

- 命令：`go build -tags gopcua -o server.exe ./cmd/server`
- 会编译 `serial/opcua.go`，需要依赖 `github.com/gopcua/opcua v0.8.0`（已在 go.mod 的 indirect 中）。
- 若 gopcua 库 API 与当前代码不兼容，需按 `serial/opcua.go` 顶部注释适配 API 或版本。

### 3. 网络/代理导致构建失败

- 若出现 `dial tcp ... connectex ... connection attempt failed` 或长时间卡在 `go: downloading ...`，属于 **GOPROXY/网络** 问题。
- 建议：
  - 使用国内代理：`go env -w GOPROXY=https://goproxy.cn,direct`
  - 或确保可访问 `proxy.golang.org` 后重试 `go mod download` 与 `go build ./...`。

## 三、引用与包结构检查结果（无问题）

以下均已核对，**未发现“找不到包”或错误引用**：

| 类别 | 说明 |
|------|------|
| **模块名** | 统一使用 `go_ProFiBus`，与 `go.mod` 一致。 |
| **internal/domain** | 被引用的子包（如 channel、device、alert、config、workflow_template、rule_template、training、fusion、control、prediction、datamanagement、event、auth、datasample）均存在且路径正确。 |
| **pkg/interfaces** | 各 handler、repository 实现、application 层对 interfaces 的引用均指向 `go_ProFiBus/pkg/interfaces`，接口与实现对应。 |
| **storage 包** | 根目录 `storage` 包定义 `PostgresStore`；`internal/infrastructure/storage/store.go` 通过类型别名 `PostgresStore = root.PostgresStore` 暴露，各 repository 使用的 `*PostgresStore` 或 `*storage.PostgresStore` 均指向同一类型，无冲突。 |
| **channel_repository** | 显式使用 `go_ProFiBus/storage` 的 `*storage.PostgresStore`，与 store 别名一致。 |
| **api/server** | 使用 `storageOld "go_ProFiBus/storage"` 的 `*storageOld.PostgresStore`，与根 `storage.PostgresStore` 一致。 |

## 四、库版本与兼容性说明

- **go.sum** 中记录的版本与 **go.mod** 一致；在能正常下载依赖的前提下，当前组合可构建。
- **Go 1.20** 与当前 go.mod 中依赖的兼容性：常见库（gin、pgx、yaml、golang.org/x/* 等）均支持 Go 1.20。
- 若将来升级到 **Go 1.21+**，可：
  - 将 `go.mod` 中 `go` 改为对应版本（如 `1.21`）。
  - 需要时再加回 `toolchain` 行。

## 五、建议自检命令（在可联网环境）

```bash
cd e:\code\go_ProFiBus
go mod verify
go mod download
go build -o server.exe ./cmd/server
# 若需 OPC-UA：
go build -tags gopcua -o server.exe ./cmd/server
```

若上述命令均成功，则说明**无引用错误、无库版本导致的“找不到”问题**；若失败，请根据报错判断是网络问题还是某依赖的 API 不兼容（如 gopcua），再针对性处理。
