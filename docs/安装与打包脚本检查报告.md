## 一、安装脚本与打包脚本

### 1.1 现状

- **安装脚本**：仓库内**没有**独立的“安装脚本”（如 `install.sh`）。安装方式以文档为主：
  - README / docs/DEPLOYMENT.md：Docker Compose、Kubernetes、本地开发。
- **打包/构建**：
  - **Dockerfile**：多阶段构建（Go 后端 + Node 前端 → 最终 Alpine 镜像），作为主要“打包”方式。
  - **CI/CD**：`.github/workflows/ci-cd.yml` 负责测试、安全扫描、构建并推送 Docker 镜像、部署到 Staging/Production。
- **唯一 Shell 脚本**：`scripts/healthcheck.sh`，用于健康检查（/health、/ping、/api/v1/pipelines），被 CI 部署后调用。

### 1.2 已修复问题

- **Dockerfile 中 `configs` 目录缺失**  
  - 问题：`COPY --from=builder /build/configs /app/configs` 时，builder 阶段没有 `configs` 目录（项目根目录只有 `config.yaml`），会导致构建失败。  
  - 修复：在 builder 阶段增加 `RUN mkdir -p /build/configs && cp /build/config.yaml /build/configs/ 2>/dev/null || true`，保证 `/build/configs` 存在且可被拷贝到最终镜像。

### 1.3 需您后续确认的问题

- **Docker 构建入口 `./cmd/server` 不存在**  
  - Dockerfile 中 `go build ... -o /build/profibus ./cmd/server`，但仓库中**没有** `cmd/server` 目录或 `cmd/server/main.go`。  
  - 当前与 API 服务器相关的 main 在 `examples/rest_api/main.go`，且其调用的 `api.NewServer` 签名已变（参数更多），直接改用该 example 作为构建入口可能无法通过编译。  
  - **建议**：在仓库中新增 `cmd/server/main.go`，作为唯一生产入口，在其中完成依赖注入并调用 `api.NewServer` 与 `Start()`；Dockerfile 继续使用 `./cmd/server` 构建。若您已有未提交的 `cmd/server`，可提交后保持 Dockerfile 不变。

- **.dockerignore 中排除了 `deployments/`**  
  - 若 Docker 构建过程不需要 `deployments/`，可保持现状；若希望镜像内包含部署示例，需从 `.dockerignore` 中移除 `deployments/`。
